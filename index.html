Sentinel API Reference

The Sentinel REST API lets you start dependency scans, retrieve findings, and manage suppressions programmatically. Use it to integrate Sentinel into CI/CD pipelines, build custom dashboards, or automate remediation workflows.

Base URL https://api.sentinel-cli.dev/v1

Authentication

All requests require an API key passed in the Authorization header. Generate one in Settings → API keys. Keys are scoped to a workspace and expire after 90 days by default.

http
Authorization: Bearer <your-api-key>
Scopes
ScopeDescription
scans:readRead scan results and findings
scans:writeStart and cancel scans
suppressions:writeCreate and delete suppressions

Versioning

The API version is included in the URL path (/v1). Breaking changes are introduced in new versions with at least 90 days notice. Non-breaking additions — new fields, new endpoints — may be added at any time.

Rate limits

PlanRequests per minute
Free30
Pro300
EnterpriseCustom

Responses include X-RateLimit-Limit, X-RateLimit-Remaining, and X-RateLimit-Reset (Unix timestamp) headers. When the limit is exceeded the API returns 429 Too Many Requests. Wait until X-RateLimit-Reset before retrying.

Scans

POST /scans Start a scan ▾

Starts a new dependency scan for a project. Sentinel detects the manifest type automatically, or you can specify it explicitly. Returns immediately with a queued scan — poll GET /scans/{id} for status.

Request body
FieldTypeDescription
project_id required string The ID of the project to scan
ref optional string Git ref to scan (branch, tag, or commit SHA). Defaults to the project's default branch
manifest optional string Manifest type: npm, pip, go, nuget. Auto-detected if omitted
profile optional string Scan profile ID. Applies custom severity thresholds and exclusions
bash Request 
curl -X POST \
  https://api.sentinel-cli.dev/v1/scans \
  -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "project_id": "proj_4kR9mNx2",
    "ref": "main",
    "manifest": "npm"
  }'
json 202 Accepted 
{
  "id": "scan_7vQpLw3X",
  "status": "queued",
  "project_id": "proj_4kR9mNx2",
  "ref": "main",
  "manifest": "npm",
  "created_at": "2025-06-20T09:14:32Z",
  "links": {
    "self": "/v1/scans/scan_7vQpLw3X",
    "findings": "/v1/scans/scan_7vQpLw3X/findings"
  }
}

POST /scans/{scan_id}/cancel Cancel a scan ▾

Cancels a scan that is queued or running. Has no effect on completed or already-cancelled scans. Returns the updated scan object.

Use this endpoint to abort long-running scans in CI environments when a pipeline is cancelled upstream.

GET /findings/{finding_id} Get a finding ▾

Returns a single finding by ID. Same schema as items in the list response, with full vulnerability detail including CVE references.

Suppressions

Mark a finding as intentionally ignored. Suppressed findings are excluded from scan summaries until the suppression is removed or expires.

POST /findings/{finding_id}/suppress Create a suppression ▾
Request body
FieldTypeDescription
reason required string One of: false_positive, accepted_risk, not_applicable
note optional string Free-text explanation. Visible to teammates and in audit logs
expires_at optional string ISO 8601 datetime. The suppression lifts automatically after this time
bashRequest
curl -X POST \
  .../findings/find_2mBvKq9Z/suppress \
  -H "Authorization: Bearer $KEY" \
  -d '{
    "reason": "not_applicable",
    "note": "Template is never called with untrusted input.",
    "expires_at": "2025-12-31T00:00:00Z"
  }'
json201 Created
{
  "id": "supp_9nRkWm1P",
  "finding_id": "find_2mBvKq9Z",
  "reason": "not_applicable",
  "created_by": "user_5jXqAb2N",
  "created_at": "2025-06-20T10:02:44Z",
  "expires_at": "2025-12-31T00:00:00Z"
}
DELETE /findings/{finding_id}/suppress Delete a suppression ▾

Removes the suppression. The finding returns to open status and appears in future scan summaries. Returns 204 No Content.

Errors

All errors follow a consistent shape. Include request_id when contacting support — it identifies the exact request in Sentinel's logs.

jsonError object
{
  "error": {
    "code": "resource_not_found",
    "message": "No scan found with ID scan_7vQpLw3X.",
    "request_id": "req_3KmNpQ8v"
  }
}

401API key is missing, invalid, or expired

Examples

Poll for scan completion (Python)
python
# Scans are asynchronous — start one, then poll until it completes.
import time, requests

HEADERS = {"Authorization": f"Bearer {API_KEY}"}

resp = requests.post(f"{BASE_URL}/scans", headers=HEADERS, json={
    "project_id": "proj_4kR9mNx2",
    "ref": "main"
})
scan_id = resp.json()["id"]

while True:
    scan = requests.get(f"{BASE_URL}/scans/{scan_id}", headers=HEADERS).json()
    status = scan["status"]
    if status in ("completed", "failed", "cancelled"):
        break
    time.sleep(5)

if status == "completed":
    s = scan["summary"]
    print(f"{s['critical']} critical · {s['high']} high")
Fail a CI build on critical findings (bash)
bash
#!/bin/bash
set -e

SCAN_ID=$(curl -s -X POST "$BASE_URL/scans" \
  -H "Authorization: Bearer $SENTINEL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"project_id": "'"$PROJECT_ID"'", "ref": "'"$GIT_SHA"'"}' \
  | jq -r '.id')

# Poll until complete (add exponential backoff in production)
while true; do
  STATUS=$(curl -s "$BASE_URL/scans/$SCAN_ID" \
    -H "Authorization: Bearer $SENTINEL_API_KEY" \
    | jq -r '.status')
  [ "$STATUS" = "completed" ] && break
  sleep 5
done

CRITICAL=$(curl -s "$BASE_URL/scans/$SCAN_ID" \
  -H "Authorization: Bearer $SENTINEL_API_KEY" \
  | jq '.summary.critical')

if [ "$CRITICAL" -gt 0 ]; then
  echo "Build failed: $CRITICAL critical vulnerabilities found."
  exit 1
fi

echo "Scan passed."
